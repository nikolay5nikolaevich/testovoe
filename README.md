# Мини-синхронизатор заявок

**Демо:** https://testovoe-ooobs-sync-unx3.vercel.app/

| Адрес | Что отдаёт |
|---|---|
| `GET /` | В браузере — HTML-страница с таблицами; для `curl`/скриптов — JSON строго по ТЗ |
| `GET /api/clients` | JSON строго по ТЗ (`clients` + `stats`) — всегда |
| `GET /api/dropped` | Заявки с невалидным телефоном (id, имя, исходный номер) |

## Как работает
- Заявки забираются с `https://test.ooobs.ru/api/orders` при запросе, кэш 60 с. При сбое источника отдаётся последний удачный результат.
- Телефон приводится к `+7XXXXXXXXXX`: ровно 11 цифр, первая 7 или 8. Остальное отбрасывается как невалидное.
- Дубль по телефону: остаётся запись с максимальным `amount`, при равенстве — более поздняя по `created_at`.
- Идемпотентность: результат — чистая функция от входных данных, без хранилища. Повторная синхронизация даёт тот же ответ, дубли не копятся.

## Отброшенные номера
Их можно уточнить у клиентов, чтобы не потерять (список — на `/api/dropped`):
- id 9, Павел Орлов — `9005551212` (10 цифр, без кода страны)
- id 14–17 — `123`, пустой, `не указан`, `+7 999` (связаться нельзя)

## Секреты
Секретов нет: источник публичный, без ключей. Если понадобятся — только через Environment Variables в Vercel, не в коде и не в репозитории.

## Структура
```
ooobs-sync/
  sync.js          нормализация, дедупликация, статистика, кэш
  api/clients.js   GET /api/clients
  api/dropped.js   GET /api/dropped
  public/site.html HTML-страница
  vercel.json      маршрутизация /
  test.js          проверки (npm test)
```

## Запуск
```
cd ooobs-sync
npm test            # Node 18+
npx vercel --prod   # деплой
```
